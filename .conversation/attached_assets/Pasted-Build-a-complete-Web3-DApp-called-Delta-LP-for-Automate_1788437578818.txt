==================================================
CORE PRODUCT
==================================================

Delta LP allows users to:

1. Connect an EVM wallet.
2. Select a token pair.
3. Select a Uniswap V3-compatible fee tier.
4. Choose a concentrated liquidity price range.
5. Deposit liquidity.
6. Create a real Uniswap V3 LP position NFT.
7. Set an automated take-profit / exit price.
8. Monitor the LP position.
9. When the target price is reached, the automation system can close the LP position.
10. Remove liquidity and collect fees.
11. Return the resulting assets to the user's wallet.

Core concept:

"Provide liquidity. Set your exit price. Let Delta close the position automatically."

SMART CONTRACT ARCHITECTURE
==================================================

Create a clean Solidity architecture.

Potential components:

DeltaAutomation.sol
DeltaPositionManager.sol

libraries/

The contract should NOT blindly take custody of user funds.

Design permissions carefully.

The automation mechanism must only be able to perform the actions explicitly authorized by the position owner.

Users should be able to cancel automation.

Include emergency/revert protection where appropriate.

Use OpenZeppelin contracts where appropriate.

Use ReentrancyGuard / SafeERC20 / Ownable or equivalent access control where appropriate.

Do not implement unsafe arbitrary token transfers.

Do not allow the keeper to withdraw unrelated user funds.

==================================================
PRICE ORACLE / TARGET PRICE
==================================================

The target-price trigger must be designed carefully.

Do not rely on an easily manipulated spot price from a single pool without protection.

Create a price validation layer.

Use the appropriate configured Uniswap pool/TWAP or another reliable oracle mechanism.

Document the price source used by the automation.

Prevent obvious price manipulation from triggering an unwanted close.

Target direction must be explicit:

Take profit when price >= target
OR
Take profit when price <= target

depending on the position configuration.

==================================================
AUTOMATION BACKEND
==================================================

Create a backend worker architecture.

The worker should:

1. Load active automation rules.
2. Read the relevant pool price.
3. Validate the price.
4. Check whether target condition is satisfied.
5. Verify the position is still active.
6. Submit the authorized close transaction.
7. Wait for confirmation.
8. Update automation status.

Do NOT hardcode private keys.

Use:

AUTOMATION_PRIVATE_KEY

from environment variables only.

Never expose the private key to frontend code.

Never put secrets in VITE_ variables.

If automation wallet is not configured, display:

"Automation keeper is not configured."

The app must still run normally.
